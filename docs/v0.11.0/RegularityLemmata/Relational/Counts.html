    Ordered and injective relation counts #

    Phase 8 unit 4 (design freeze in ARCHITECTURE.md): ordered and injective counts are separate APIs — no unqualified "count" names, no silent reuse of hypergraph semantics.

    relationCountOn counts satisfying tuples on a heterogeneous box (wrapping the tuple substrate's tupleCount); relationCount is the full ordered count over all tuples Fin n → V, diagonals included — the canonical first-order count. injectiveRelationCount filters through injectiveTuples, and the public nonInjectiveRelationCount is its exact complement:

    relationCount = injectiveRelationCount + nonInjectiveRelationCount

    (relationCount_eq_injective_add_nonInjective), from which the collision bound via Phase 1's nonInjectiveMaps follows. Densities: relationDensity is normalized by |V|^n, injectiveRelationDensity by the falling factorial — never the injective count by |V|^n. Both obey the guard-free x / 0 = 0 convention.

    Permanent tests: the diagonal binary relation on Fin 2 has ordered count 2 and injective count 0; a true nullary relation on the empty carrier has both counts 1; a false one has both 0; above the arity bound there is no symbol to count.
